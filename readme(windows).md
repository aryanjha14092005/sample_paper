# AIOps Sample Paper --- PowerShell Terminal Commands Guide

This README contains the PowerShell commands required to execute
Questions 1--5 of the AIOps sample paper.

> **Environment:** Windows 10/11 + PowerShell **Python:** Python 3.x
> **Kafka:** Kafka 4.3.1 **Airflow:** WSL2 or Docker is recommended
> because Apache Airflow does not natively support Windows.

------------------------------------------------------------------------

# Initial Python Setup

## 1. Go to the project

If the project is on your Desktop:

``` powershell
cd "$HOME\Desktop\sample-paper"
```

``` powershell
Get-Location
```

## 2. Create virtual environment

``` powershell
python -m venv .venv
```

------------------------------------------------------------------------

## 3. Activate virtual environment

``` powershell
.\.venv\Scripts\Activate.ps1
```

``` powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Then activate again:

``` powershell
.\.venv\Scripts\Activate.ps1
```

You should see something similar to:

``` text
(.venv) PS C:\Users\YourName\Desktop\sample-paper>
```

``` powershell
pip install pandas matplotlib kafka-python
```

Or, if `requirements.txt` is present:



# Q2 --- Kafka Topic and Producer

Q2 requires Kafka, a `server_metrics` topic, and a Python producer.

> The commands below assume Kafka has been extracted to:
>
> `C:\kafka_2.13-4.3.1`

If your Kafka folder is somewhere else, change the path accordingly.

------------------------------------------------------------------------

## Step 1 --- Go to Kafka

``` powershell
cd "C:\kafka_2.13-4.3.1"
```

Verify:

``` powershell
Get-ChildItem
```

You should see directories such as:

``` text
bin
config
libs
```

------------------------------------------------------------------------

## Step 2 --- Generate Kafka UUID

``` powershell
.\bin\windows\kafka-storage.bat random-uuid
```

Copy the UUID generated by this command.

Example:

``` text
TybTfQ-8RTK74eZvfBnNIw
```

------------------------------------------------------------------------

## Step 3 --- Remove old KRaft data

Use this only when doing a fresh Kafka setup.

If your Kafka data directory is:

``` text
C:\tmp\kraft-combined-logs
```

run:

``` powershell
Remove-Item -Recurse -Force "C:\tmp\kraft-combined-logs"
```

If the directory does not exist, PowerShell may report an error. That is
fine for a fresh setup.

------------------------------------------------------------------------

## Step 4 --- Format Kafka storage

Replace `YOUR_UUID` with the UUID generated above.

``` powershell
.\bin\windows\kafka-storage.bat format --standalone -t YOUR_UUID -c .\config\server.properties
```

Example:

``` powershell
.\bin\windows\kafka-storage.bat format --standalone -t TybTfQ-8RTK74eZvfBnNIw -c .\config\server.properties
```

------------------------------------------------------------------------

## Step 5 --- Verify Kafka metadata

Depending on your Kafka configuration, the metadata file will be inside
the KRaft log directory.

For example:

``` powershell
Get-Content "C:\tmp\kraft-combined-logs\meta.properties"
```

------------------------------------------------------------------------

## Step 6 --- Start Kafka

``` powershell
.\bin\windows\kafka-server-start.bat .\config\server.properties
```

Keep this terminal running.

Do **not** close it.

------------------------------------------------------------------------

## Step 7 --- Open another PowerShell terminal

Open a new PowerShell window and run:

``` powershell
cd "C:\kafka_2.13-4.3.1"
```

------------------------------------------------------------------------

## Step 8 --- Check Kafka connection

``` powershell
.\bin\windows\kafka-broker-api-versions.bat --bootstrap-server localhost:9092
```

If Kafka is running correctly, broker information should be displayed.

------------------------------------------------------------------------

## Step 9 --- Create `server_metrics` topic

``` powershell
.\bin\windows\kafka-topics.bat --create --topic server_metrics --bootstrap-server localhost:9092
```

------------------------------------------------------------------------

## Step 10 --- List topics

``` powershell
.\bin\windows\kafka-topics.bat --list --bootstrap-server localhost:9092
```

Make sure:

``` text
server_metrics
```

appears.

------------------------------------------------------------------------

## Step 11 --- Describe the topic

``` powershell
.\bin\windows\kafka-topics.bat --describe --topic server_metrics --bootstrap-server localhost:9092
```

------------------------------------------------------------------------

## Step 12 --- Go to the Python project

Open another PowerShell terminal:

``` powershell
cd "$HOME\Desktop\sample-paper"
```

Activate the Python environment:

``` powershell
.\.venv\Scripts\Activate.ps1
```

------------------------------------------------------------------------

## Step 13 --- Install Kafka Python library

``` powershell
pip install kafka-python
```

------------------------------------------------------------------------

## Step 14 --- Run the producer

``` powershell
python .\q2_kafka_producer\producer.py
```

The producer sends at least 10 server-metric messages to:

``` text
server_metrics
```

------------------------------------------------------------------------

## Step 15 --- Verify Kafka messages

Open another PowerShell terminal:

``` powershell
cd "C:\kafka_2.13-4.3.1"
```

Run:

``` powershell
.\bin\windows\kafka-console-consumer.bat --topic server_metrics --bootstrap-server localhost:9092 --from-beginning
```

You should see the messages published by the Python producer.

Example:

``` text
{"server_id": "server01", "cpu_usage": 82, "memory_usage": 65}
{"server_id": "server02", "cpu_usage": 75, "memory_usage": 62}
...
```

Stop the console consumer:

``` text
Ctrl + C
```

# Q4 --- Apache Airflow AIOps Workflow

> **Important:** Apache Airflow does not natively support Windows.
>
> For Windows, use **WSL2 or Docker** for the Airflow section.
>
> The commands below assume the Airflow environment is running inside
> WSL2.

The project Python environment and Airflow environment are separate.

Project Python environment:

``` text
Windows:
C:\Users\YourName\Desktop\sample-paper\.venv
```

Airflow environment inside WSL:

``` text
~/airflow-venv
```

------------------------------------------------------------------------

## Step 1 --- Open WSL

From PowerShell:

``` powershell
wsl
```

You are now inside the Linux environment.

------------------------------------------------------------------------

## Step 2 --- Set Airflow home

Inside WSL:

``` bash
export AIRFLOW_HOME=~/airflow-class
```

------------------------------------------------------------------------

## Step 3 --- Check Airflow

``` bash
~/airflow-venv/bin/airflow version
```

------------------------------------------------------------------------

## Step 4 --- Go to the project

If your Windows project is located at:

``` text
C:\Users\YourName\Desktop\sample-paper
```

then from WSL:

``` bash
cd /mnt/c/Users/YourName/Desktop/sample-paper
```

------------------------------------------------------------------------

## Step 5 --- Create Airflow DAG folder

``` bash
mkdir -p q4_airflow/dags
```

The DAG file should be located at:

``` text
q4_airflow/dags/aiops_workflow.py
```

------------------------------------------------------------------------

## Step 6 --- Copy DAG to Airflow

``` bash
cp q4_airflow/dags/aiops_workflow.py ~/airflow-class/dags/
```

------------------------------------------------------------------------

## Step 7 --- Verify DAG file

``` bash
ls ~/airflow-class/dags
```

Make sure:

``` text
aiops_workflow.py
```

is present.

------------------------------------------------------------------------

## Step 8 --- Start Airflow

``` bash
export AIRFLOW_HOME=~/airflow-class
```

Then:

``` bash
~/airflow-venv/bin/airflow standalone
```

Keep this terminal running.

------------------------------------------------------------------------

## Step 9 --- Open another WSL terminal

Open another PowerShell window and enter WSL:

``` powershell
wsl
```

Then:

``` bash
export AIRFLOW_HOME=~/airflow-class
```

------------------------------------------------------------------------

## Step 10 --- Check DAG

``` bash
~/airflow-venv/bin/airflow dags list | grep aiops
```

Expected:

``` text
aiops_workflow
```

------------------------------------------------------------------------

## Step 11 --- Check DAG tasks

``` bash
~/airflow-venv/bin/airflow tasks list aiops_workflow
```

Expected tasks:

``` text
collect_metrics
process_metrics
detect_anomaly
generate_report
```

------------------------------------------------------------------------

## Step 12 --- Check import errors

``` bash
~/airflow-venv/bin/airflow dags list-import-errors
```

There should be no import errors.

------------------------------------------------------------------------

## Step 13 --- Trigger the DAG

``` bash
~/airflow-venv/bin/airflow dags trigger aiops_workflow
```

------------------------------------------------------------------------

## Step 14 --- Check DAG runs

``` bash
~/airflow-venv/bin/airflow dags list-runs -d aiops_workflow
```

------------------------------------------------------------------------

## Airflow workflow

``` text
collect_metrics
       ↓
process_metrics
       ↓
detect_anomaly
       ↓
generate_report
```
