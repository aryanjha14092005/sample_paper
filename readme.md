# Q2 — Kafka Topic and Producer

Q2 requires Kafka, a `server_metrics` topic, and a Python producer.

## Step 1 — Go to Kafka

```bash
cd ~/kafka_2.13-4.3.1
```

---

## Step 2 — Generate Kafka UUID

```bash
bin/kafka-storage.sh random-uuid
```

Copy the UUID generated by this command.

Example:

```text
TybTfQ-8RTK74eZvfBnNIw
```

---

## Step 3 — Remove old KRaft data

Use this only when doing a fresh Kafka setup:

```bash
rm -rf /tmp/kraft-combined-logs
```

---

## Step 4 — Format Kafka storage

Replace `YOUR_UUID` with the UUID generated above.

```bash
bin/kafka-storage.sh format --standalone -t YOUR_UUID -c config/server.properties
```

Example:

```bash
bin/kafka-storage.sh format --standalone -t TybTfQ-8RTK74eZvfBnNIw -c config/server.properties
```

---

## Step 5 — Verify Kafka metadata

```bash
cat /tmp/kraft-combined-logs/meta.properties
```

---

## Step 6 — Start Kafka

```bash
bin/kafka-server-start.sh config/server.properties
```

Keep this terminal running.

---

## Step 7 — Open another terminal

```bash
cd ~/kafka_2.13-4.3.1
```

---

## Step 8 — Check Kafka connection

```bash
bin/kafka-broker-api-versions.sh --bootstrap-server localhost:9092
```

---

## Step 9 — Create `server_metrics` topic

```bash
bin/kafka-topics.sh --create \
--topic server_metrics \
--bootstrap-server localhost:9092
```

---

## Step 10 — List topics

```bash
bin/kafka-topics.sh --list \
--bootstrap-server localhost:9092
```

Make sure:

```text
server_metrics
```

appears.

---

## Step 11 — Describe the topic

```bash
bin/kafka-topics.sh --describe \
--topic server_metrics \
--bootstrap-server localhost:9092
```

---

## Step 12 — Go to the Python project

Open another terminal:

```bash
cd ~/Desktop/sample-paper
```

Activate Python environment:

```bash
source .venv/bin/activate
```

---

## Step 13 — Install Kafka Python library

```bash
pip install kafka-python
```

---

## Step 14 — Run the producer

```bash
python q2_kafka_producer/producer.py
```

The producer sends at least 10 server-metric messages.

---

## Step 15 — Verify Kafka messages

Open another terminal:

```bash
cd ~/kafka_2.13-4.3.1
```

Run:

```bash
bin/kafka-console-consumer.sh \
--topic server_metrics \
--bootstrap-server localhost:9092 \
--from-beginning
```

You should see the messages.

Stop the console consumer:

```text
Ctrl + C
```

# Q4 — Apache Airflow AIOps Workflow

Airflow uses a **separate virtual environment**.

Project Python environment:

```text
~/Desktop/sample-paper/.venv
```

Airflow environment:

```text
~/airflow-venv
```

---

## Step 1 — Set Airflow home

```bash
export AIRFLOW_HOME=~/airflow-class
```

---

## Step 2 — Check Airflow

```bash
~/airflow-venv/bin/airflow version
```

---

## Step 3 — Go to project

```bash
cd ~/Desktop/sample-paper
```

---

## Step 4 — Create Airflow DAG folder

```bash
mkdir -p q4_airflow/dags
```

The DAG file should be located at:

```text
q4_airflow/dags/aiops_workflow.py
```

---

## Step 5 — Copy DAG to Airflow

```bash
cp q4_airflow/dags/aiops_workflow.py ~/airflow-class/dags/
```

---

## Step 6 — Verify DAG file

```bash
ls ~/airflow-class/dags
```

Make sure:

```text
aiops_workflow.py
```

is present.

---

## Step 7 — Start Airflow

```bash
export AIRFLOW_HOME=~/airflow-class
```

```bash
~/airflow-venv/bin/airflow standalone
```

Keep this terminal running.

---

## Step 8 — Open another terminal

```bash
export AIRFLOW_HOME=~/airflow-class
```

---

## Step 9 — Check DAG

```bash
~/airflow-venv/bin/airflow dags list | grep aiops
```

Expected:

```text
aiops_workflow
```

---

## Step 10 — Check DAG tasks

```bash
~/airflow-venv/bin/airflow tasks list aiops_workflow
```

Expected tasks:

```text
collect_metrics
process_metrics
detect_anomaly
generate_report
```

---

## Step 11 — Check import errors

```bash
~/airflow-venv/bin/airflow dags list-import-errors
```

---

## Step 12 — Trigger the DAG

```bash
~/airflow-venv/bin/airflow dags trigger aiops_workflow
```

---

## Step 13 — Check DAG runs

```bash
~/airflow-venv/bin/airflow dags list-runs -d aiops_workflow
```

---

## Airflow workflow

```text
collect_metrics
       ↓
process_metrics
       ↓
detect_anomaly
       ↓
generate_report
```
